| S1 | Arkiv SDK API shapes (`executeBatch`, create params, flags option, ownership change params) | 2026-11-04 | @arkiv-network/sdk 1.0.1 + viem 2.57.7 / Rabdi 7794095 | `executeBatch({creates, patches, deletes, extensions, ownershipChanges}, txParams?)` → `{txHash, createdEntities, patchedEntities, deletedEntities, extendedEntities, ownershipChanges}`. Create item: `{schema, values, expiration: ExpirationTime.*, flags?: {readonly?, permissionlessExtension?}, salt?}`; ownership change `{entityKey, newOwner}`; extension `{entityKey, expiration}`; `patchEntity(schema, key, {set})`. The SDK encodes ops in a fixed order (creates, patches, deletes, extensions, ownership changes), whatever order we pass. `predictEntityKeys({owner, count \| salts})` is a **public** action → `[{key, salt}]`, keyed by the registry's per-owner `entityNonce` (not the tx nonce). `txParams = {gas?, nonce?, gasPrice?}`; with `gas` given the SDK skips its estimate. Queries: `select().from(schema).createdBy().where(eq, gte…).orderBy(asc(…)).limit(≤100).offset().fetch()`; attribute values come back typed as `{type, value}`. `watchEntityEvents` events carry key/owner/expiry, no schema or attrs. viem is a peer dep. Rabdi's `eth_estimateGas` drops revert data, so decode engine errors with `eth_call` | Adapter (`packages/arkiv`) written against these shapes. Scripts: `tools/spikes/` |
