| S12 | MCP TS SDK transport-level proxying (no high-level Server) incl. Streamable HTTP session handling | 2026-11-02 | @modelcontextprotocol/sdk 1.32.1 | **stdio part confirmed.** `StdioServerTransport` ↔ `StdioClientTransport` (and `InMemoryTransport` in tests) forward `JSONRPCMessage` objects; responses deep-equal direct ones, progress, cancellation and `roots/list` pass through. Gotchas: `StdioClientTransport` only inherits a minimal env by default (we pass the full env minus `AFR_*`); `StdioServerTransport` doesn't signal stdin EOF as close (the CLI listens for `stdin.end`). **HTTP half confirmed (2026-11-03):** one `StreamableHTTPServerTransport` per downstream session (keyed by `mcp-session-id`) plus one upstream connection per session, all sharing one Recorder/chain. Responses through the proxy deep-equal direct HTTP responses (tools/list, results, isError, progress). | S13 | noble sync signing + better-sqlite3 hot-path p99 on target hardware | 2026-11-02 | @noble/curves 2.4.0, Node 22.23, 4-core dev box under load (load avg ≈ 3) | Partial (no SQLite yet). noble `sign` ≈ 0.85–1.1 ms with base-point precompute; keccak of a 2 KiB header ≈ 0.13 ms. Core build+hash+sign of a ~2 KiB header run alone (`pnpm --filter @afr/core bench`): p50 1.27 ms, p99 2.7–2.9 ms. **T9 (≤ 1 ms p99) is not met on this box** | Re-measure on the CI runner in P1-18. If still over: inject a native signer (OpenSSL via `node:crypto` + recovery-id search) from the recorder, keeping core pure. The phase target (proxy hot path p99 < 5 ms) is still reachable. **R5 measured 2026-11-03** (`pnpm --filter @afr/recorder bench`, full `capture()`: normalise + JCS + keccak + sign + AES-GCM + SQLite insert, 2 KiB args, run alone, load avg ≈ 5): p50 ≈ 2.0 ms, p99 4.4–6.1 ms across 5 runs; borderline. CPU profile: secp256k1 ≈ 27 %, keccak ≈ 16 %, AES-GCM ≈ 9 %, SQLite ≈ 8 %. CI gates R5 at 5 ms; T9 not gated. **Tail cause found 2026-11-04:** SQLite's WAL auto-checkpoint (1000 pages) ran inside the committing insert: ~20 ms stalls every ~220 captures, mostly not GC. Fix: `wal_autocheckpoint = 0` + PASSIVE checkpoints every 1 s from a second connection in a worker thread (falls back to auto-checkpoint if the worker exits); journal bodies sealed with native `node:crypto` AES-256-GCM (same layout, still opened with noble). After: p50 ≈ 1.6 ms, p99 3.4–3.8 ms over 3 runs (load avg ≈ 3); exit-demo proxy round trip p99 84 → 20 ms |
